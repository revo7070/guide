Основа: «Гайд Демо 2027 [ver.1.0.3 Build 4]», 81 страница.
Стенд: PNETLab, Debian 13, 7 узлов.

ВАЖНО
- Команды ниже выполняются от root, если отдельно не указано другое.
- В nano сохранить: Ctrl+O, Enter; выйти: Ctrl+X.
- В PNETLab подключите Additional.iso к нужной ВМ через CD/DVD и смонтируйте/откройте образ. В гайде он извлекается через Xarchiver в /root. После извлечения файлы находятся в /root/Additional.
- Перед сетевыми изменениями проверьте имена интерфейсов: ip -br a.
- Не вставляйте команды с приглашением root@...# — вводится только сама команда.
- Пароли и адреса приведены по исходному PDF. Если в вашей топологии интерфейсы названы иначе, заменяйте только имя интерфейса, не IP.

2.2. Включить маршрутизацию IPv4 на ISP, HQ-RTR, BR-RTR, BR-FW

На каждом из четырёх узлов:
nano /etc/sysctl.d/sysctl.conf

Вписать:
net.ipv4.ip_forward=1

Сохранить, затем применить:
sysctl --system

2.3. Настроить NAT на ISP, HQ-RTR, BR-RTR, BR-FW

На каждом из четырёх узлов:
nano /etc/nftables.conf

Содержимое для NAT:

#!/usr/sbin/nft -f

flush ruleset

table ip nat {
    chain postrouting {
        type nat hook postrouting priority 100; policy accept
        meta l4proto { gre, ipip, ospf } counter return
        masquerade
    }
}

table inet filter {
    chain input {
        type filter hook input priority filter;
    }
    chain forward {
        type filter hook forward priority filter;
    }
    chain output {
        type filter hook output priority filter;
    }
}

Сохранить. На ISP дополнительно применить:
nft -f /etc/nftables.conf

4. VLAN И OPEN VSWITCH (МОДУЛЬ 1, ЗАДАНИЕ 4)

На HQ-RTR:
apt update
apt install -y openvswitch-switch

Создать виртуальный коммутатор:
ovs-vsctl add-br hq-sw

Добавить физические интерфейсы с тегами:
ovs-vsctl add-port hq-sw ens4 tag=100
ovs-vsctl add-port hq-sw ens5 tag=200
ovs-vsctl add-port hq-sw ens6 tag=999

Добавить VLAN-интерфейсы:
ovs-vsctl add-port hq-sw vlan100 tag=100 -- set interface vlan100 type=internal
ovs-vsctl add-port hq-sw vlan200 tag=200 -- set interface vlan200 type=internal
ovs-vsctl add-port hq-sw vlan999 tag=999 -- set interface vlan999 type=internal

Теперь в /etc/network/interfaces на HQ-RTR замените настройки адресов на VLAN-интерфейсы. В итоге фрагмент должен выглядеть так:

auto ens3
iface ens3 inet static
address 172.16.1.2/28
gateway 172.16.1.1

auto vlan100
iface vlan100 inet static
address 192.168.100.1/27

auto vlan200
iface vlan200 inet static
address 192.168.200.1/28

auto vlan999
iface vlan999 inet static
address 192.168.99.1/29

post-up nft -f /etc/nftables.conf
post-up ip link set hq-sw up

Перезапустить сеть:
systemctl restart networking

В гайде указано, что после перезапуска IP могут задвоиться. Если так произошло:
reboot

Проверка на HQ-RTR:
ip -br a
ping -c 3 192.168.100.2
ping -c 3 192.168.200.5

Проверить управление по VLAN999:
apt install -y openssh-server

С HQ-SRV:
ssh net_admin@192.168.99.1

При первом подключении ответить yes, пароль P@ssw0rd.

11. SAMBA AD DC НА BR-SRV (МОДУЛЬ 2, ЗАДАНИЕ 1)

ВАЖНО: на BR-SRV в /etc/resolv.conf должен быть nameserver 192.168.100.2.

На BR-SRV установить пакеты:
apt update
apt install -y samba smbclient winbind libnss-winbind krb5-user net-tools samba-ad-provision

При настройке krb5-user укажите:
Realm: AU-TEAM.IRPO
KDC: br-srv.au-team.irpo
Административный сервер: br-srv.au-team.irpo

Удалить стандартную конфигурацию:
mv /etc/samba/smb.conf /etc/samba/smb.conf.bak

Остановить службы:
systemctl stop smbd nmbd winbind

Создать домен:
samba-tool domain provision

В мастере:
- Realm: AU-TEAM.IRPO
- Domain: AU-TEAM
- Server Role: dc
- DNS backend: SAMBA_INTERNAL
- DNS forwarder: 192.168.100.2 (если запрашивается)
- Administrator password: P@ssw0rd
Остальные значения — по умолчанию (Enter), как указано в гайде.

Настроить политику паролей:
samba-tool domain passwordsettings set --min-pwd-length=8
samba-tool domain passwordsettings set --account-lockout-threshold=5
samba-tool domain passwordsettings set --account-lockout-duration=30
samba-tool domain passwordsettings set --reset-account-lockout-after=30

Запуск служб:
systemctl unmask samba-ad-dc
systemctl enable --now samba-ad-dc

Скопировать Kerberos-конфиг:
cp /var/lib/samba/private/krb5.conf /etc/krb5.conf

Создать группу:
samba-tool group add hq

Создать пользователей:
samba-tool user create hquser1 P@ssw0rd
samba-tool user create hquser2 P@ssw0rd
samba-tool user create hquser3 P@ssw0rd
samba-tool user create hquser4 P@ssw0rd
samba-tool user create hquser5 P@ssw0rd

Добавить пользователей в группу:
samba-tool group addmembers hq hquser1
samba-tool group addmembers hq hquser2
samba-tool group addmembers hq hquser3
samba-tool group addmembers hq hquser4
samba-tool group addmembers hq hquser5

19. NGINX REVERSE PROXY НА ISP (МОДУЛЬ 3, ЗАДАНИЕ 2)

На ISP:

- web.au-team.irpo → http://172.16.1.2:8080
- docker.au-team.irpo → http://172.16.2.2:8080

Пример HTTP-конфигурации:

server {
    listen 80;
    server_name web.au-team.irpo;
    location / {
        proxy_pass http://172.16.1.2:8080;

        proxy_set_header X-Real-IP $remote_addr;

server {
    listen 80;
    server_name docker.au-team.irpo;
    location / {
        proxy_pass http://172.16.2.2:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

ln -s /etc/nginx/sites-available/proxy /etc/nginx/sites-enabled/proxy
rm -f /etc/nginx/sites-enabled/default

Открыть основной конфиг:
nano /etc/nginx/nginx.conf

Найти строку server_names_hash_bucket_size 64; и убрать #.

21. ЦЕНТР СЕРТИФИКАЦИИ НА HQ-SRV (МОДУЛЬ 3, ЗАДАНИЕ 4)

На HQ-SRV:
mkdir -p /root/ca
cd /root/ca

Создать ключ CA:
openssl genrsa -out ca.key 2048

Создать самоподписанный сертификат CA:
openssl req -x509 -new -nodes -key ca.key -sha256 -days 365 -out ca.crt -subj "/CN=au-team.irpo"

Создать ключ и CSR для web:
openssl req -newkey rsa:2048 -nodes -keyout web.key -out web.csr -subj "/CN=web.au-team.irpo" -addext "subjectAltName=DNS:web.au-team.irpo"

Подписать сертификат web на 30 дней:
openssl x509 -req -in web.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out web.crt -days 30 -sha256 -copy_extensions copy

Создать ключ и CSR для docker:
openssl req -newkey rsa:2048 -nodes -keyout docker.key -out docker.csr -subj "/CN=docker.au-team.irpo" -addext "subjectAltName=DNS:docker.au-team.irpo"

Подписать сертификат docker на 30 дней:
openssl x509 -req -in docker.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out docker.crt -days 30 -sha256 -copy_extensions copy

На ISP установить SSH и создать каталог:
apt install -y openssh-server
mkdir -p /etc/nginx/ssl

Разрешить root SSH-доступ (временная передача файлов):
nano /etc/ssh/sshd_config

Добавить/раскомментировать:
PermitRootLogin yes

Перезапустить:
systemctl restart ssh

С HQ-SRV скопировать пять файлов на ISP:
scp /root/ca/*.crt /root/ca/*.key root@172.16.1.1:/etc/nginx/ssl/

Пароль root на ISP — тот, который задан для этой ВМ.

На ISP отредактировать конфиг:
nano /etc/nginx/sites-enabled/proxy

Настроить HTTPS-серверы на порту 443:
для web:
listen 443 ssl;
server_name web.au-team.irpo;
ssl_certificate /etc/nginx/ssl/web.crt;
ssl_certificate_key /etc/nginx/ssl/web.key;
auth_basic "Restricted Access";
auth_basic_user_file /etc/nginx/.htpasswd;
location / {
    proxy_pass http://172.16.1.2:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

для docker:
listen 443 ssl;
server_name docker.au-team.irpo;
ssl_certificate /etc/nginx/ssl/docker.crt;
ssl_certificate_key /etc/nginx/ssl/docker.key;
location / {
    proxy_pass http://172.16.2.2:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Accept-Encoding "";
    sub_filter 'http://docker.au-team.irpo' 'https://docker.au-team.irpo';
    sub_filter_once off;
}

Проверить:
nginx -t
systemctl restart nginx

С HQ-SRV скопировать CA на HQ-CLI:
scp /root/ca/ca.crt sshuser@192.168.200.5:/tmp/

На HQ-CLI запустить Яндекс.Браузер:
yandex-browser-stable --no-sandbox

В адресной строке:
browser://settings/certificates

Далее:

2) «Установленные вами».
3) В «Доверенных сертификатах» нажать «Импорт».
4) Ctrl+L, путь /tmp/, выбрать ca.crt.
5) Убедиться, что появился сертификат au-team.irpo.
6) Полностью закрыть браузер и открыть заново.

Проверить:
https://web.au-team.irpo
https://docker.au-team.irpo

Для web ввести WEB / P@ssw0rd. Предупреждений сертификата быть не должно.

ВАЖНЫЕ ЗАМЕЧАНИЯ ПО ИСХОДНОМУ PDF

1) В оригинальном PDF часть содержимого конфигурационных файлов показана только на скриншотах. Для таких мест текстовое распознавание не всегда передаёт каждую строку. Сверяйте спорные фрагменты с соответствующей страницей исходного PDF.
2) В заданиях с Additional.iso обязательны именно файлы из образа: compose.yaml, Docker tar-образы, import.sh, users.csv, get_hostname_address.yml. Не заменяйте их произвольными файлами.
3) В сетевых заданиях сначала добейтесь базовой связности и DNS, только после этого переходите к Samba, Ansible, веб-приложениям и сертификатам.
4) После изменения /etc/network/interfaces проверяйте ip -br a и ip route. Ошибка в имени интерфейса может полностью отключить связь.
5) Пароль root из начального входа, пароли пользователей и пароль администратора Samba — разные учётные записи. Не путайте их.
